# خطة البرنامج الموحد والتقارير (Unified Platform & Reporting)

---

## 1. المعمارية المقترحة للنظام

```
[ واجهة المستخدم: رابط URL أو مجلد محلي ]
                  │
                  ▼
      [ المحرك الموحد (Orchestrator) ]
        ├── تخطيط المهمة (Scan Planner)
        ├── تشغيل الأدوات بالتوازي/التتابع (Runners / Adapters)
        └── تجميع المخرجات الخام (Raw Outputs)
                  │
                  ▼
    [ طبقة التوحيد (SARIF / JSON Normalizer) ]
                  │
                  ▼
    [ قاعدة البيانات المحلية (SQLite) ]
        ├── المشاريع (Projects)
        ├── الفحوصات (Scan Runs)
        ├── الثغرات الموحدة (Findings)
        └── محرك المقارنة (Diff / Re-test Engine)
                  │
                  ▼
  [ التقرير المجمع (HTML / PDF / Markdown / JSON) ]
```

---

## 2. نموذج الثغرة الموحد (Unified Finding Schema)
لدمج نتائج أدوات مختلفة في تقرير واحد بدون تكرار أو تشتت، يتم تحويل كل نتيجة إلى هذا الهيكل:

- `fingerprint`: بصمة فريدة للثغرة (تُحسب من: نوع الثغرة + الملف/الرابط + السطر/العنصر) لتسهيل تتبعها عبر الفحوصات المتكررة.
- `title`: عنوان واضح للمشكلة.
- `severity`: مستوى الخطورة الموحد (`Critical`, `High`, `Medium`, `Low`, `Info`).
- `category`: نوع الفحص (`DAST`, `SAST`, `SCA`, `Secrets`, `IaC`).
- `sourceTool`: اسم الأداة التي اكتشفتها (مثل `Semgrep`, `Nuclei`, `Trivy`).
- `location`: المسار المحلي (`file:line`) أو الرابط المتأثر (`URL / Endpoint`).
- `description`: شرح المشكلة وأثرها الأمني.
- `remediation`: خطوات الإصلاح المقترحة (أو النسخة الآمنة للمكتبة).
- `status`: حالة المتابعة (`Open`, `Fixed`, `In Progress`, `False Positive`).

---

## 3. آلية إعادة الاختبار وتتبع الحلول (Re-testing Workflow)
1. **الفحص الأول (Baseline Scan):** يكتشف المشاكل ويرصدها في التقرير برقم `Scan #1`.
2. **مرحلة الإصلاح:** تعمل على حل الثغرات في الكود أو إعدادات السيرفر.
3. **إعادة الفحص (`Re-test` / `Scan #2`):** يقوم البرنامج بتشغيل نفس الأدوات (أو أداة محددة للتحقق السريع) ومقارنة البصمات (`fingerprint`) مع `Scan #1`:
   - أي ثغرة اختفت تُعلّم تلقائياً كـ **`Fixed`** (تم الحل).
   - أي ثغرة ما زالت موجودة تبقى **`Open`** (قيد المعالجة).
   - أي ثغرة لم تكن موجودة سابقاً تُعلّم كـ **`New`** (جديدة).
4. **مؤشر التحسن:** يعرض التقرير المجمع نسبة الإغلاق (مثلاً: تم حل 12 من أصل 15 ثغرة).

---

## 4. مخرجات التقارير المخططة
- **لوحة تفاعلية (Interactive HTML Report):** قابلة للفلترة حسب الخطورة، الأداة، والحالة (`Open` / `Fixed`).
- **ملخص تنفيذي وتقني (Markdown / PDF):** مناسب للمراجعة أو الأرشفة.
- **قائمة مهام للمطور (Actionable Checklist):** مرتبة من الأعلى خطورة إلى الأقل.
